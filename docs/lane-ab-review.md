## Lane A 是否恢复交易

**不建议现在恢复。它刚刚在“暂停”状态下实际交易，并且权益从 51.73 降到约 27.70。**

恢复门槛：

1. 确认 VPS 主机身份，重新建立可信 SSH。不要在未确认的机器上放私钥。
2. 参数文件显式写 `inventory_box=40`、`max_leg_risk=12`、`max_market_usd=25`、`min_hours_to_resolution=24`、`min_mid=0.30`、`max_mid=0.70`。
3. 启用 `pmm-alerts.timer`，先跑 24 小时纸面。验收：单腿成交占比 < 50%，配对率 > 70%，滚动 100 笔净捕获 > 0，现金从未低于 20 且无挂单。
4. 极小实盘：1 个市场、20 股、每日最大亏损 5 pUSD、单市场最大 25 pUSD、库存箱 40。连续 3 天满足验收才扩到 2 个市场。
5. 任何一天出现“单腿敞口 > 40 股”或“现金 < 20”立即停机，不自动恢复。

**不建议做的**：直接恢复 4 个市场、原尺寸、无人工复核。第一次亏损就是单腿加金字塔，当前代码只是加了边界，没有消除单腿。

## Lane A 的优化优先级

1. **限时补腿/平仓**。单腿成交后 30–60 秒内没有配对，就按可接受损失退出，或挂一个不会扩大敞口的补腿单。这是 ADR 0013 留下的最大缺口。
2. **单市场日亏损上限**。当前有单腿风险上限，没有“这个市场今天已经亏了多少就停”的累计上限。
3. **告警变硬熔断**。`single_leg_flow` 或 `unpaired_exposure` 命中时，写 `quoting_enabled=false`，而不是只发通知。
4. **恢复前的纸面账本**。纸面模式必须记录“如果真实下单会不会成交”，否则配对率仍然是推测。

## ML 是否值得加入

**现在不值得。先把数据补齐，再谈模型。**

原因：

- Lane A 的“胜率”不是方向胜率。配对 maker 的指标是配对完成率、单腿损失、扣费后净捕获。用“胜率”做标签会把配对成交和单腿赌博混在一起。
- 现有样本是 111 笔成交、21 个市场，而且大部分是失败样本。这个量级训练不出可用的 spread 模型。
- journal 目前没有完整的报价时盘口特征。没有 quote-time book、spread、depth、volatility、time-to-resolution，模型只能学市场名字。
- 自调参已经是规则基线，每小时最多改一个参数。任何 ML 必须先打败这个基线。

建议的实验顺序：

1. **先记录，不训练**。每轮报价落盘：市场、mid、spread、depth、reward band、time-to-resolution、size、quote price、是否成交、成交后 60 秒的 mid、最终结算、单腿/配对。
2. **目标先选单腿损失**。标签：成交后 60 秒标记价相对成交价不利超过 X 分，或该腿最终归零。这个目标比“spread 最优”更直接，也更容易验证。
3. **基线**：规则闸门 + 现有 self_tune。逻辑回归只作为可解释对照。样本至少 500 笔有标签成交、30 个市场、跨 2 周。
4. **验证**：按时间切分，walk-forward，不能随机打乱；报告 AUC、Brier、以及按阈值行动后的净捕获。AUC 提升但净捕获不提升，不上线。
5. **上线位置**：先做毒性/单腿门控，不直接改 spread。模型推断延迟预算 < 20ms。先影子运行 1 周，再考虑拦截。
6. **样本不足时明确写 inconclusive**，不要用 111 笔成交调 LightGBM。
